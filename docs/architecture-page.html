탕탕 시스템 구성도

실제 코드와 배포 설정을 읽어서 그린 구성도다. 기획 문서가 아니라 지금 돌아가는 것을 그렸고, 아직 구현되지 않은 경로는 색과 선으로 구분했다.

기준일 2026-08-14 Java 17 · Spring Framework 5.3.39 MyBatis 3.5.16 · MySQL 8 Vue 3 + Vite Tomcat 9 (war)
런타임 호출 배포 파이프라인 미구현 경로 미구현 컴포넌트

01배포 구성

프론트는 Vercel, 백엔드는 EC2 한 대에 컨테이너 세 개다. 브라우저는 Vercel 도메인 하나하고만 통신하고, /api/* 는 Vercel 이 EC2 로 넘긴다.

컨테이너내용포트영속 데이터
apiSpring Legacy WAR · Tomcat 98080 : 8080업로드 이미지 볼륨
mockCODEF 대역 목 서버 (별도 레포)8081 : 8080없음
dbMySQL 8.0 · tangtang + financial_mock3307 : 3306mysql_data 볼륨
nginx 는 쓰지 않는다. 초기 기획 문서에 남아 있지만 docker-compose.yml 에 없다. 리버스 프록시 역할은 Vercel 의 rewrite 가 대신한다.
배포는 한 줄로 끝난다. main · dev 에 push 되면 GitHub Actions 가 EC2 에 SSH 로 붙어 git pull → docker compose up --build -d → 15초 뒤 헬스체크를 한다. 헬스체크가 실패하면 컨테이너 로그를 남기고 워크플로가 실패한다.
부하 측정치를 읽을 때 반드시 감안할 것. DB · 목 서버 · API 가 한 대에 같이 떠 있다. 서로 CPU 를 나눠 쓰므로 로컬 측정치보다 낮게 나온다.

02애플리케이션 모듈

프로세스는 하나다. 그 안에서 모듈을 논리적으로만 나눴다. 브로커는 없고 모듈 사이는 Spring Event 로 잇는다.

03모듈을 잇는 세 개의 이벤트

이벤트가 세 개인데 전달 방식이 전부 다르다. 편해서가 아니라 각각 이유가 있다. 이 표가 이 프로젝트에서 가장 설명할 거리가 많은 부분이다.

04데이터 파이프라인

서비스의 핵심 흐름이다. 계좌를 연동해 거래를 모으고, 반복 결제를 찾아내고, 그걸 근거로 미션과 리포트를 만든다. 지금 한 칸이 비어 있다.

발표에서는 “미구현”이 아니라 “어느 칸이 남았다” 로 말할 수 있다. tbl_transaction 을 읽는 코드는 6곳인데 INSERT 하는 코드는 0곳이다.

05로그인과 토큰

구글 OAuth 를 쓰지만 리디렉션 목적지가 프론트 도메인이라, 브라우저 입장에서는 처음부터 끝까지 한 origin 이다.

리디렉션 목적지가 프론트 도메인이라 쿠키가 Vercel 도메인 한 곳에만 심긴다. origin 이 하나로 통일돼 CORS 와 쿠키 전달 문제가 구조적으로 생기지 않는다.

06알림 전달과 실패 처리

브로커를 걷어내면서 잃은 것이 실패한 메시지를 다시 처리할 곳이었다. 그래서 테이블과 배치로 직접 만들었다.

SSE 를 EventSource 로 받지 않는다. fetch + ReadableStream 이다. Service Worker 를 넣는다면 /api/ 는 손대지 말고 그대로 흘려보내야 한다. 안 그러면 알림이 버퍼링돼 죽는다.

07배치 스케줄

배치 프레임워크는 없다. 스프링 스케줄러 여덟 개가 전부이고, 실행 시각이 서로 겹치지 않게 어긋나 있다.

스케줄러 전용 스레드풀이 반드시 있어야 한다. 없으면 스프링이 단일 스레드로 폴백한다. 응답 없는 SSE 클라이언트 하나가 send() 에서 막히면 모든 사용자의 하트비트가 멈춘다. 하트비트가 막으려던 바로 그 상황이다.

08그리면서 확인된 것

문서가 아니라 코드에서 확인한 사실이다. 발표 질의응답에서 쓰일 만한 것들을 모았다.

항목실제
nginx 쓰지 않는다. 기획 문서에만 남아 있고 docker-compose.yml 에 없다
거래내역 수집 tbl_transaction 에 INSERT 하는 코드가 0곳. 현재 유일한 경로는 시드 SQL
스프링 컨텍스트 둘로 나뉜다. 서블릿 쪽은 컨트롤러와 예외 처리만, 루트 쪽은 나머지 전부
환경 설정 APP_ENV 로 한 번에 하나만 로드. 두 개를 나열했다가 기동 실패한 이력이 있다
API 응답 전부 공통 래퍼로 감싼다. 업무 오류는 400, 인증 실패만 401
API 문서 Springfox 로 코드에서 생성. 엔드포인트 54개가 모듈별 섹션 7개로 묶여 있다
확인이 필요한 것 두 가지. Swagger 문서가 인증 없이 열린다. 인터셉터가 /api/** 전용이라 문서 경로는 통과한다. 그리고 로컬 API 가 MySQL 에 root 로 붙고 있다. 배포본도 그런지 확인해야 한다.
실제 코드와 docker-compose.yml · deploy.yml · vercel.json 을 읽어 작성했다. 기획 의도와 컨셉은 별도 문서에 있고, 두 문서가 다르면 이쪽이 현재 상태다.
